## 本章小结

本章讲主线的第一个条件：不可信内容从哪些门进入智能体。七扇门各有形态，也各有已经发生过的案例。

### 1. 核心要点回顾

**工具与协议**：工具描述和参数说明是模型会读、用户看不见的文本；MCP 的风险分连接、分发、授权三个环节，本地 Server 的每条启动命令都是代码执行入口；令牌要受众绑定、最短时效、绝不透传。

**技能市场**：是审核更弱、单个包权限更大的软件包仓库，2026 年已被大规模投毒；恶意技能把载荷写在给智能体看的说明文档里，并同时使用恶意代码和提示注入两层手法。

**记忆**：一次注入可以被持久化，经由不可信内容写入、仅通过正常交互写入、直接投毒记忆库三种路径都有实证。

**URL 与屏幕**：访问一个链接就能外泄数据；屏幕上的一切像素都可能是指令，浏览器智能体使同源策略等传统防线失效。

**人**：人工审核会被审批疲劳淹没，用户会被智能体的输出反向操纵。

**其他智能体**：同伴的消息是数据不是指令；注入会自我复制，也会伪装成报错让编排者改派任务；签名回答“谁发的”，不回答“能不能信”。

共同规律是：**不可信内容总是来自看起来属于内部的位置**——自己的仓库、工单、收件箱、记忆、同事智能体。按存放位置判断可信度，会系统性地漏掉不可信内容的入口。

### 2. 各节要点

- **12.1**：工具描述与参数说明是模型会读、用户看不见的文本；MCP 的风险分连接、分发、授权三个环节，本地 Server 的每条启动命令都是代码执行入口；令牌要受众绑定、最短时效、绝不透传。
- **12.2**：技能市场是审核更弱、单个包权限更大的软件包仓库，2026 年已被大规模投毒；载荷同时用恶意代码与提示注入两层，扫描要覆盖两层，处置还要轮换凭据、清理记忆。
- **12.3**：一次注入可被持久化到记忆，三种写入路径都有实证；治理按“持久的不可信输入通道”设计：来源与时间戳、写入门控、对用户可见、检索隔离、过期与复核。
- **12.4**：访问一个链接就能外泄数据，参数进入服务端日志即告泄露；注入驱动的链接访问、公开 URL 重定向链路与页面背景加载都能触发；防御要把注入整体防御、运行时监控、红队与敏感数据分级结合起来。
- **12.5**：屏幕上的一切像素都可能是指令，浏览器智能体使同源策略等传统防线失效；加固靠会话隔离、站点范围限定、高风险动作人工确认、屏上内容一律不可信、动作级审计。
- **12.6**：人也是攻击面：审批疲劳（OWASP Agentic 威胁 T10）让人机械点击，人类操纵（T15）借智能体的可信位置反向操纵用户。
- **12.7**：同伴智能体的输出是数据不是指令；注入会自我复制，也会伪装成报错让编排者改派任务；防御靠结构化消息通道、权限不随委托放大、预先固定允许的调用关系；签名只回答“谁发的”。

### 3. 延伸思考

1. 为你的系统列出不可信内容入口的完整清单，包括工具描述、记忆和同伴消息。
2. 其中哪些来源是按存放位置而不是按作者判断可信度的？
