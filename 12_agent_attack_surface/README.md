# 第十二章 智能体的攻击面

[11.3](../11_agent_foundations/11.3_unreliable_executor.md) 主线的第二项要求是盘点不可信的来源。本章逐行展开 [11.2](../11_agent_foundations/11.2_threat_model.md) 来源总表中除“模型本身”之外的各行（[12.1.4](12.1_tool_security.md) 的工具调用幻觉也涉及“模型本身”一行），分析每个来源的入口。工具与 MCP 协议、技能市场、长期记忆、URL、屏幕上的像素、人本身，以及其他智能体的消息，各有其形态和已发生的案例。[第十三章](../13_agent_architecture/README.md)讨论如何管控这些入口。

## 学习目标

读完本章，读者应能：

1. 为自己的系统列出不可信内容入口的完整清单，包括工具描述、记忆和同伴消息，并指出其中哪些来源是按存放位置而不是按作者判断可信度的。
2. 说明工具描述、MCP 启动命令和 OAuth 令牌各自带来什么风险，以及固定描述哈希、沙箱运行本地 Server、令牌受众绑定且绝不透传等对应措施。
3. 判断技能安装、记忆写入和出站请求时应检查哪几项：代码与说明文档两层扫描，记忆的来源与写入门控，出站是否只经一个默认拒绝的代理口。
4. 区分签名能回答的“这条消息是谁发的”与它不能回答的“这条消息能不能信”，并据此约束智能体之间的消息通道与权限委托。
5. 解释人工审核为何会被审批疲劳和人类操纵削弱，以及确认界面应展示什么、批准应绑定到什么。

## 本章结构

- [12.1](12.1_tool_security.md) 工具调用安全：工具的参数、描述和返回值如何被攻击者利用，MCP 协议在连接、分发、授权三个环节有哪些风险与防护
- [12.2](12.2_agent_skills.md) 技能与生态安全：技能市场为何是审核更弱、权限更大的软件包仓库，2026 年的大规模投毒用了哪些手法、应如何防护
- [12.3](12.3_memory_poisoning.md) 记忆与状态污染：一次注入如何被写入记忆而持久化，写入侧应如何把关
- [12.4](12.4_url_exfiltration.md) URL 驱动的数据外泄：为什么无需“说出”数据、访问一个链接即可外泄，哪一层防御是确定性的
- [12.5](12.5_computer_use_browser.md) 计算机使用与浏览器智能体：为什么屏幕上的一切都可能是指令，部署时应如何加固
- [12.6](12.6_human_layer.md) 人机交互层的威胁：作为闸的人如何被审批疲劳淹没、被智能体的输出操纵
- [12.7](12.7_multi_agent_security.md) 多智能体系统的安全：同伴的消息为何是数据而非指令，已有实证的自我复制与控制流劫持说明了什么，信任边界如何划分

各节按入口排列：12.1、12.2 讲智能体主动接入的工具与技能，12.3 讲跨会话保留的记忆，12.4、12.5 讲网络链接与屏幕这两类外部内容，12.6、12.7 讲人和其他智能体。每节按“入口是什么 → 攻击方式与案例 → 防御”的顺序展开，节末给出相关章节。

> **⚠️ 道德边界**：本章对各类攻击面的剖析用于让智能体开发者识别并修复自身系统的安全弱点；针对未经授权的他方系统执行类似攻击违反法律与服务条款。完整声明见 [§4 章首道德边界与负责任披露说明](../04_prompt_injection/README.md)。
