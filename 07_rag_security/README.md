# 第七章 RAG 与知识库安全

检索增强生成（RAG）是指将外部知识库接入模型：先按用户问题从知识库检索相关片段，再将片段连同问题一起交给模型生成答案。RAG 是企业利用私有数据的主要方式，也是不可信内容进入模型上下文的第一道入口：谁能向知识库写入内容，谁就能向模型下达指令；谁能影响检索排序，谁就能决定模型看到什么。本章以间接提示注入（[4.3 节](../04_prompt_injection/4.3_indirect_injection.md)）和长上下文中的投毒（[4.6 节](../04_prompt_injection/4.6_long_context_risks.md)）为原理基础，分析这一入口的攻击与防御；智能体的记忆与检索共用同一套机制，其风险在[第十二章](../12_agent_attack_surface/README.md)继续讨论。

## 学习目标

读完本章，读者应能：

1. 指出 RAG 流水线中入库、存储、授权、召回、进入上下文各环节分别面临哪些攻击。
2. 解释知识库投毒为什么是少量、靶向、可优化的精确攻击，并说明隔离聚合、过滤、离线扫描、事后溯源等防御各自的代价。
3. 判断一条摄取管线是否按处理不可信输入的标准部署：解析是否在沙箱中进行，隐藏文本是否在压平前检测，切块是否带来源标记。
4. 检查检索时的授权是否先于内容交付：过滤条件由谁生成，切块与缓存是否继承权限，过度共享是否已先行修复。
5. 设计 RAG 安全评测：分别报告检索成功率、条件生成成功率、总 ASR 与正常任务效用，并写出各自的分母。

## 本章结构

- [7.1](7.1_rag_architecture.md) RAG 架构与攻击面：RAG 由哪些组件构成，每个组件对应什么攻击。
- [7.2](7.2_knowledge_base_poisoning.md) 知识库投毒攻击：攻击者需要注入多少内容才能控制回答，从 PoisonedRAG 到单文档、拆分式与触发词后门；防御各自的代价；互联网规模的语料投毒。
- [7.3](7.3_retrieval_manipulation.md) 检索结果操纵：攻击者用哪些手段使恶意内容进入召回结果，检索器层面能做什么，如何定位“被召回”发生在哪一环节。
- [7.4](7.4_ingestion_pipeline.md) 文档摄取管线安全：解析器漏洞、隐藏文本与多模态注入如何经摄取管线进入知识库，摄取环节应做哪些防护。
- [7.5](7.5_vector_database_security.md) 向量数据库与嵌入安全：嵌入为何不是匿名化数据，向量库有哪些已披露的漏洞与危险默认配置，多租户隔离的边界在哪里。
- [7.6](7.6_retrieval_access_control.md) 检索时的访问控制：授权应在检索的哪一步执行，云平台提供了哪些机制，过度共享与混淆代理为何在授权正确时仍会造成泄露。
- [7.7](7.7_context_window_attacks.md) 上下文窗口攻击：恶意内容进入上下文后如何起作用，生产系统中出现过哪些实例。
- [7.8](7.8_rag_evaluation_best_practices.md) 评测与最佳实践：有哪些可用的基准，如何把链路失败拆成检索、授权、生成各自带分母的可测条件，入库、检索、生成三层各有哪些防护要点。

各节按“先全貌、再攻击、后环节、最后检验”的顺序展开：7.1 给出架构与攻击面全图；7.2、7.3 讲攻击者如何让恶意内容被召回；7.4 至 7.7 沿流水线依次讲内容如何入库（7.4）、如何存储（7.5）、谁有权检索到什么（7.6）、如何进入上下文（7.7），每一环节都给出相应的攻击与防御；7.8 用基准与指标检验这些防御。

> **⚠️ 道德边界**：本章对知识库投毒与检索操纵的剖析用于让 RAG 系统的建设者识别并修复自身系统的弱点；针对未经授权的他方系统执行类似攻击违反法律与服务条款。完整声明见 [§4 章首道德边界与负责任披露说明](../04_prompt_injection/README.md)。
