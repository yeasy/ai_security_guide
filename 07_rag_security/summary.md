## 本章小结

RAG 把知识库接到模型上，也把知识库变成了攻击者可以瞄准的目标。本章把它当作一条流水线来分析：内容如何入库、如何被召回、如何进入上下文，每一环各有攻击与防御。

### 1. 核心要点回顾

**攻击面是一条流水线**：入库、存储、权限、召回、进入上下文，每一环都有攻击；谁能向知识库写入内容，谁就能向模型下指令。

**知识库投毒是精确攻击**：PoisonedRAG 每个目标问题约 5 条文本即可达到约 90% 的成功率；之后的工作把条件放宽到单文档、无需已知问题、拆分成看似无害的多段、触发词后门和拒答型拒绝服务。防御各有代价——隔离聚合把推理时间拉长到 1.16 至 3.65 倍，可证明的准确率只有干净准确率的一半左右；横向基准的结论是现有防御无法提供稳健保护。互联网规模的语料投毒已经在发生。

**摄取管线在处理攻击者的文件**：解析器漏洞、隐藏文本（5 个加载器、357 个场景下 74.4% 的成功率；18 篇稿件的真实事件）与多模态注入都是现实威胁；解析要在沙箱里做，隐藏文本要在压平前检测。

**向量库要按敏感数据运维**：嵌入可被反演；认证绕过、跨租户访问、文件路径型漏洞和预认证代码执行都已披露；多个产品默认不开认证，暴露实例以千计；管理端口必须网络隔离。

**访问控制必须前置**：过滤条件由应用按已认证身份生成，不能由模型生成或由不可信输入拼接；云平台的文档级过滤各有边界；先修过度共享再接知识库；攻击者在自己有权写入的地方放内容就能让 RAG 替他读文档。

**检索结果仍是不可信输入**：穿过检索进入上下文的内容按第四章的间接注入处理；GeminiJack 的修复是拆分组件，而不是更好的检测。

### 2. 防御矩阵

| 环节 | 关键防护措施 |
|------|--------------|
| 摄取 | 解析在沙箱中进行、依赖固定版本、压平前的隐藏文本检测、来源标记、图像与元数据按不可信处理 |
| 存储 | 向量库认证与管理端口隔离、快照与日志只向最小权限开放、静态加密、独立索引或租户过滤 |
| 权限 | 前置过滤、过滤条件由应用生成、权限同步与切块继承、先修过度共享 |
| 检索 | 来源可信度加权、混合检索与多来源印证、相似度阈值、异常检测 |
| 生成 | 检索结果按不可信内容处理、由无工具的模型实例读取、来源标记、输出校验 |
| 验证 | 用 SafeRAG 等基准加自适应攻击定期测试 |

### 3. 延伸思考

1. 你的知识库里，谁能写入内容？这些人是否都被当作可信来源？
2. 如果攻击者只能向知识库添加 5 条文本，他能让你的系统对哪个问题给出错误答案？
3. 检索前的权限过滤是否真的在检索前？
