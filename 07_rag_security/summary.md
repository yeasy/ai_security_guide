## 本章小结

本章把 RAG 当作一条内容入库、存储、授权、召回、进入上下文的流水线，逐环节分析攻击与防御，并说明如何用写明分母的指标检验防御。

### 1. 核心要点

- 谁能向知识库写入内容，谁就能向模型下达指令；流水线的每一环节都存在攻击（7.1）。
- 知识库投毒是精确攻击：PoisonedRAG 每个目标问题约 5 条文本即可达到约 90% 的成功率，横向评测显示现有防御无法提供稳健保护（7.2）。
- 混合检索与重排只提高操纵成本，检索侧的硬约束是按可信身份限制可交付的文档（7.3）。
- 摄取管线在处理攻击者的文件，解析要在沙箱里做，隐藏文本要在压平前检测（7.4）。
- 向量库要按敏感数据运维，因为嵌入可被反演、多个产品默认不开认证（7.5）。
- 授权必须先于内容交付，过滤条件由应用按已认证身份生成，不能由模型生成或由不可信输入拼接（7.6）。
- 通过检索进入上下文的内容始终是不可信输入，GeminiJack 的修复是拆分组件而不是更好的检测（7.7）。
- 评测要加入自适应攻击，并分别报告检索成功、条件生成成功、总 ASR 与正常效用（7.8）。

### 2. 各节要点

- [7.1 RAG 架构与攻击面](7.1_rag_architecture.md)：入库、存储、权限、召回、进入上下文，每一环节都存在攻击。
- [7.2 知识库投毒攻击](7.2_knowledge_base_poisoning.md)：PoisonedRAG 之后的工作把条件放宽到单文档、无需已知问题、拆分成看似无害的多段、触发词后门和拒答型拒绝服务。防御各有代价：隔离聚合使推理时间增至 1.16 至 3.65 倍，可证明的准确率只有干净准确率的一半左右；互联网规模的语料投毒已经在发生。
- [7.3 检索结果操纵](7.3_retrieval_manipulation.md)：“被召回”要说明到达了哪一环节；ACL 保护的是机密性，允许读取的投毒文档仍可能进入上下文。
- [7.4 文档摄取管线安全](7.4_ingestion_pipeline.md)：解析器漏洞、隐藏文本（5 个加载器、357 个场景下 74.4% 的成功率；18 篇稿件的真实事件）与多模态注入都是现实威胁。
- [7.5 向量数据库与嵌入安全](7.5_vector_database_security.md)：认证绕过、跨租户访问、文件路径型漏洞和预认证代码执行都已披露；仅 Chroma 暴露在互联网上的实例就逾千个；管理端口必须网络隔离。
- [7.6 检索时的访问控制](7.6_retrieval_access_control.md)：ANN 内部过滤模式另有召回与成本权衡；同租户缓存还要绑定用户、范围与权限版本，并在命中后复核当前 ACL；云平台的文档级过滤各有边界；先修过度共享再接知识库；攻击者在自己有权写入的地方放内容就能让 RAG 替他读文档。
- [7.7 上下文窗口攻击](7.7_context_window_attacks.md)：通过检索进入上下文的内容按[第四章](../04_prompt_injection/README.md)的间接注入处理；上下文完整性需要端到端保护。
- [7.8 评测与最佳实践](7.8_rag_evaluation_best_practices.md)：写出各指标的分母，固定上下文与固定载荷的诊断不能替代完整链路评测；防护按摄取、检索、生成三层组织。

### 3. 防御矩阵

| 环节 | 关键防护措施 |
|------|--------------|
| 摄取 | 解析在沙箱中进行、依赖固定版本、压平前的隐藏文本检测、来源标记、图像与元数据按不可信处理 |
| 存储 | 向量库认证与管理端口隔离、快照与日志只向最小权限开放、静态加密、独立索引或租户过滤 |
| 权限 | 正文交付前授权、过滤条件由应用生成、权限同步与切块继承、先修过度共享 |
| 检索 | 来源可信度加权、混合检索与多来源印证、相似度阈值、异常检测 |
| 生成 | 检索结果按不可信内容处理、由无工具的模型实例读取、来源标记、输出校验 |
| 验证 | 用 SafeRAG 等基准加自适应攻击定期测试 |

### 4. 延伸思考

1. 你的知识库里，谁能写入内容？这些人是否都被当作可信来源？
2. 如果攻击者只能向知识库添加 5 条文本，他能让你的系统对哪个问题给出错误答案？
3. 未授权正文能否在被拒绝前到达上下文、重排器、缓存或日志？权限撤销后，旧缓存是否仍可能被使用？
