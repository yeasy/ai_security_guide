# 第十三章 智能体安全架构

防御只有四种形态：隔离不可信内容、收窄敏感访问、管住对外动作，三项都必须保留时则加监督。本章讨论动作闸和这四种形态在架构上的实现，范围限于模型出错或被说服之后仍然成立的机制：能力拆分、控制流与数据流隔离、沙箱与出站控制、身份与委托（不问原因的不可逆操作网关见 [13.1.5](13.1_agents_rule_of_two.md)）。使模型“更难被骗”的措施有用，但只能降低频率，不能设定上界，这类措施在[第四章](../04_prompt_injection/README.md)和[第九章](../09_io_protection/README.md)讨论。

- **[13.1](13.1_agents_rule_of_two.md) Rule of Two 与能力拆分**：三项条件如何去掉其一、三项都需要时如何监督，以及已披露案例的检验
- **[13.2](13.2_architectural_defenses.md) 提示注入的架构级防御**：六种设计模式、CaMeL 与信息流控制，使不可信数据无法改变控制流、敏感数据无法流向未授权出口
- **[13.3](13.3_sandbox_egress.md) 执行沙箱与出站控制**：文件系统、网络与凭据三条边界的工程实现
- **[13.4](13.4_agent_identity.md) 智能体身份与委托授权**：智能体以什么身份访问资源，权限如何随委托衰减
- **[13.5](13.5_tooling_selection.md) 工具与方案选型**：策略引擎、护栏、网关、MCP 扫描、沙箱、身份、可观测性与红队八类工具，各自保证什么、文档承认不做什么

[第十四章](../14_agent_practice/README.md)把本章的方法应用于一个完整系统，并给出全景图与评审清单。
