# 第十三章 智能体安全架构

防御只有四种形态：不读、不拿、不做，三项都必须保留时则盯着。本章讲这四种形态怎样落到架构上，并且只讲在模型已经被说服之后仍然成立的那些机制——能力拆分、控制流与数据流隔离、沙箱与出站控制、身份与委托。让模型“更难被骗”的措施有用，但只能降低频率，不能设定上界，它们在第四章和第九章讨论。

- **13.1 Rule of Two 与能力拆分**：三项能力去其一怎么去，三项都要时怎么盯，并用已披露的案例检验
- **13.2 提示注入的架构级防御**：六种设计模式、CaMeL 与信息流控制，让不可信数据改不了控制流、敏感数据流不到未授权出口
- **13.3 执行沙箱与出站控制**：文件系统、网络与凭据三条边界的工程实现
- **13.4 智能体身份与委托授权**：智能体以什么身份访问资源，权限如何随委托衰减
- **13.5 工具与方案选型**：策略引擎、护栏、网关、MCP 扫描、沙箱、身份、可观测性与红队八类工具，各自保证什么、文档承认不做什么

本章的方法在第十四章用一个完整系统演练一遍，并给出全景图与评审清单。
