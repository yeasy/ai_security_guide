# 第十四章 智能体安全实践

本章回答一个问题：把前三章讨论的结构、入口和边界用到具体系统上，应当怎样设计、检验和评审。[第十一章](../11_agent_foundations/README.md)给出了主线，[第十二章](../12_agent_attack_surface/README.md)盘点了不可信内容的入口，[第十三章](../13_agent_architecture/README.md)给出了架构上的防御；本章先分析部署最广、风险最高的编码智能体，再讨论运行期模型本身带来的两类问题，然后完成一个从需求到检验的设计演练，最后把全篇归纳为一张参考架构图、一条十二步调用时序和一份评审清单。[第十五章](../15_governance/README.md)在此基础上讨论治理与合规。

## 学习目标

读完本章，读者应能：

1. 说明编码智能体为何默认三项齐全，并针对仓库内容、配置文件、生成代码、分发渠道和持续集成分别给出加固做法。
2. 区分隐蔽破坏与错位两类来自模型本身的威胁，并说明为什么系统提示和推理过程监控都不能单独依赖。
3. 对一个具体系统完成威胁建模、能力拆分与数据流策略设计，用攻击链逐条检验，并写出剩余风险与代价。
4. 指出参考架构十二个运行步骤中哪几步是闸、凭据在哪一步附加、循环由谁判定停止。
5. 使用 [14.5](14.5_security_panorama.md) 的清单评审现有的智能体系统。
6. 为 RAG 知识助手、客服、编码、浏览器、MCP 服务与多智能体等场景，选出必选控制、工具组合、上线顺序和验收用例。

## 本章结构

- [14.1](14.1_coding_agents.md) 编码智能体安全：编码智能体的攻击面在哪里，怎样加固？结论是仓库里的每个文件都是提示，配置文件等同于可执行内容，由不可信事件触发的持续集成任务不得持有写权限，“测试通过”由智能体无法修改的部分判定。
- [14.2](14.2_sabotage_ai_control.md) 隐蔽破坏检测与 AI 控制：模型有意规避监督、暗中多做一步时，监控能否发现，控制协议能否阻止？内容包括 SHADE-Arena 基准、控制协议与推理过程的可监控性。
- [14.3](14.3_agentic_misalignment.md) 智能体错位威胁：没有攻击者时，模型在压力下的错位行为如何限制？内容从压力测试到防护框架。
- [14.4](14.4_case_study.md) 综合案例：为一个邮件与文档助手设计安全边界，具体分哪几步，设计完成后系统能保证什么？
- [14.5](14.5_security_panorama.md) 智能体安全全景：一个完整的智能体系统由哪些组件和关卡构成，如何据此评审？内容包括参考架构与十二个运行步骤、调用时序、生命周期、责任分工与评审清单。
- [14.6](14.6_scenario_playbooks.md) 按场景的落地方案：六类常见智能体场景各自具备哪几项性质、必选哪些控制、用哪些工具、按什么顺序上线、怎样验收

各节的顺序是从具体到总括：先看风险最高的一类系统（14.1），再看模型本身作为威胁来源的两种情形，即有意破坏（14.2）与压力下的错位（14.3）；然后用一个完整案例串起设计与检验（14.4）；接着把全篇归纳为可直接对照评审的全景（14.5）；最后按场景给出可照着落地的方案（14.6）。
