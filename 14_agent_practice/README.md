# 第十四章 智能体安全实践

安全设计需要在完整任务中验证：仓库内容如何影响命令，模型能否绕过监督，授权能否绑定到实际执行参数，以及失败后是否留下可核对的记录。本章用具体系统和测试场景检验这些问题。

## 学习目标

读完本章，读者应能：

1. 为邮件与文档助手完成威胁建模、能力拆分与数据流策略设计，用攻击链检验设计，并记录剩余风险与代价。
2. 沿一次请求标出策略检查、人工确认、凭据附加与停止条件，用安全全景清单评审各组件的职责。
3. 说明编码智能体为何默认三项齐全，并针对仓库内容、配置文件、生成代码、分发渠道和持续集成给出加固做法。
4. 为 RAG 知识助手、客服、浏览器、MCP 服务与多智能体等场景，选出必选控制、工具组合、上线顺序和验收用例。
5. 在支付场景中检查授权与实际执行参数的绑定，并验证预算和状态变化下的执行边界。
6. 区分隐蔽破坏与错位评测各自检验的问题，说明系统提示和推理过程监控不能单独提供哪些保证。

## 阅读路径

**先完成一个案例。** [14.1](14.1_case_study.md) 从邮件与文档助手的朴素实现出发，依次完成威胁建模、控制设计和攻击复验；[14.2](14.2_security_panorama.md) 再把案例归纳为运行时序、组件职责与评审清单。

**再迁移到业务场景。** [14.3](14.3_coding_agents.md) 深入编码智能体的仓库、命令与持续集成边界；[14.4](14.4_scenario_playbooks.md) 将控制点用于其他场景；[14.5](14.5_payment_security.md) 进一步检验支付授权与执行的一致性。

**最后检验模型本身的威胁。** [14.6](14.6_sabotage_ai_control.md) 用隐蔽破坏评估检验监督与控制协议，[14.7](14.7_agentic_misalignment.md) 用错位压力测试检查授权目标受到挑战时的行为，并据此复核前面设计的边界。
