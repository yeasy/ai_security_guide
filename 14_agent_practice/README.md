# 第十四章 智能体安全实践

前三章分别讲了结构、入口和边界。本章把它们用起来：先看部署最广、风险最高的编码智能体；再讨论运行期的两类问题——模型暗中破坏时监控能否发现，以及模型在压力下的错位行为；然后用一个邮件与文档助手从需求走到检验；最后把全篇拼成一张参考架构图、一条十二步调用时序和一份评审清单。

- **14.1 编码智能体安全**：仓库里的每个文件都是提示，配置文件等同于可执行内容，持续集成中的智能体不得持有写权限；“测试通过”由智能体改不了的部分判定
- **14.2 隐蔽破坏检测与 AI 控制**：SHADE-Arena 基准、控制协议与推理过程的可监控性
- **14.3 智能体错位威胁**：从压力测试到防护框架
- **14.4 综合案例**：为一个邮件与文档助手设计安全边界并用攻击链检验
- **14.5 智能体安全全景**：参考架构与十二个运行步骤、调用时序、生命周期、责任分工与评审清单

读完本章，读者应当能拿着 14.5 的清单去评审一个现有的智能体系统。
