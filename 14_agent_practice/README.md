# 第十四章 智能体安全实践

前三章分别讨论了结构、入口和边界，本章将其用于实践：先分析部署最广、风险最高的编码智能体；再讨论运行期的两类问题，即模型暗中破坏时监控能否发现，以及模型在压力下的错位行为；然后以一个邮件与文档助手为例，完成从需求到检验的设计；最后把全篇归纳为一张参考架构图、一条十二步调用时序和一份评审清单。

- **[14.1](14.1_coding_agents.md) 编码智能体安全**：仓库里的每个文件都是提示，配置文件等同于可执行内容，由不可信事件触发、读取不可信内容的持续集成任务不得持有写权限；“测试通过”由智能体无法修改的部分判定
- **[14.2](14.2_sabotage_ai_control.md) 隐蔽破坏检测与 AI 控制**：SHADE-Arena 基准、控制协议与推理过程的可监控性
- **[14.3](14.3_agentic_misalignment.md) 智能体错位威胁**：从压力测试到防护框架
- **[14.4](14.4_case_study.md) 综合案例**：为一个邮件与文档助手设计安全边界并用攻击链检验
- **[14.5](14.5_security_panorama.md) 智能体安全全景**：参考架构与十二个运行步骤、调用时序、生命周期、责任分工与评审清单

读完本章，读者应能使用 [14.5](14.5_security_panorama.md) 的清单评审现有的智能体系统。
